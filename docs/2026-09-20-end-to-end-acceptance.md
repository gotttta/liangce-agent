# 全链路审计实施与验收（2026-09-20）

对应 [审计文档](2026-09-20-end-to-end-audit.md)。本轮实施覆盖 14 项已确认问题，并落地 8 项设计限制的首轮改进。保留工作区原有未提交改动，没有提交运行日志。审计文档中的“只审计、不修改”描述属于上一轮，本轮按用户请求实施。

## 验收结论

- 确定性回归：新增 `tests/test_end_to_end_audit.py`，48 个用例。全量结果见下方最终验证记录。
- Docker 实测：更新宿主与 worker 二进制协议，构建 `liangce-sandbox:2`；包含真实容器隔离、超时回收、内存/PID/输出限制和 2048×2048 灰度图测试。没有在宿主执行模型生成代码。
- 真实模型：使用项目已配置的 `deepseek-v4.1-flash`，仅发送本轮生成的合成图片，未发送用户业务图片。两项最终结果通过像素、交付及实时视觉评审，仍保留用户最终确认步骤。
- 这些结果证明修复机制及两项冒烟场景可运行，不代表工业数据集准确率已经达标。工业图片、多批次模型稳定性、浏览器人工交互验收仍需实际样本。

## 设计限制的改进与边界

| 项目 | 本轮落地 | 保留边界 |
|---|---|---|
| 1 摘要取前几项 | 增加数值极值、均值、异常索引和极值样本；仍能按 selector 精确读取 | 通用统计不能代替各量测业务的异常定义 |
| 2 取证预算 | 导航独立 4 次；有效取证默认 8 次，按未解决问题可增加到 24 次；评审轮数与预算匹配 | 仍有有限预算，不能无限遍历；证据不足必须拒绝通过 |
| 3 上下文超限 | 旧工具调用及其回复成组卸载到可恢复文件，保留首条要求与最新证据；限制图片数量和编码体积，预览长边最多 2048 | 若不可卸载的必要要求仍超限则明确失败，不静默截断；没有实现任意超长用户文本的自动语义压缩 |
| 4 算子库全量源码 | 初始只注入名称、摘要与源码哈希；源码按 query_operators 检索 | 单次读回的必要源码仍受请求总预算约束 |
| 5 摘要统计 | 对话摘要纳入统一耗时、usage 和请求预算；单条超长历史分块处理 | 摘要仍由模型生成，不作为独立验收真值 |
| 6 实验/正式参数 | 两条路径共享 runner，实验从 task_contract 传 rendering/constraints/GT/unit；每次持久化 execution_spec | 第一次理解尚无最终契约时的探索有其当时 spec，正式验收使用固定契约；不能倒推探索时已知最终模型理解 |
| 7 状态复制数组 | graph state、quality、measurements、候选与记忆中大输出使用文件引用；完整输出集中保存在 raw/final 文件 | raw 与 final 故意各保留一份；历史旧大文件未做破坏性迁移 |
| 8 JSON 数组传输 | 有界二进制 ndarray 帧，验证 dtype/shape/长度，不使用 pickle/压缩；64 MiB 输入与输出独立预算 | 支持测试的 2048²；超预算仍拒绝，未实现任意尺寸图像的分块算法执行 |

首次尝试并非全部成功，记录仍保留于 `tmp/audit_acceptance/`：

1. 方块方案在试验后引入不支持的 `radius` 参数。已把完整 Pipeline 校验移到规划收尾，错误可反馈给模型同轮修正，并新增回归。
2. 首次零缺陷用例在评审期间达到测试设定的 150 秒总时限；后续 300 秒预算下完成（约 122 秒）。

4. 全量回归曾出现一次输出洪水测试被 `cleanup_failed` 覆盖，容器未残留。加强回收：先释放 attach 管道，`rm -f` 返回错误时仅在独立 inspect 明确证实容器不存在后视为回收成功，其他错误继续报告；新增竞态单测，相关 67 项测试通过。
5. 重放脚本读取首次超时状态时缺少 `understanding`，该脚本行记录为 error；最终零缺陷证据使用完整重新规划成功的运行，未将该脚本错误当作通过。

## 部署及复跑

沙箱协议升级，宿主代码和容器必须同步更新；默认镜像已改为 `liangce-sandbox:2`。本机验收镜像在已有受信沙箱依赖层上重新复制当前 core 构建，避免重复下载依赖；完整构建方式见 [Docker 文档](docker-sandbox.md)。尚未重启既有 UI 服务；正在运行的进程不会自动采用新代码。

```bash
docker build -f sandbox/Dockerfile -t liangce-sandbox:2 .
LIANGCE_REQUIRE_DOCKER_TESTS=1 .venv/bin/python -m pytest -q --disable-warnings
.venv/bin/python -m ui.app
```

网页请求默认不设总时限；`LIANGCE_REQUEST_TIMEOUT_SECONDS` 未设置或设为 `0` 时禁用总时限，设为正数时启用相应秒数的总时限，修改后需重启服务。模型网络超时、Docker 沙箱限额和规划轮数限制仍生效。取消为协作式：在模型流、工具、节点和 Docker 读写边界检查；网络单次等待受 SDK 超时约束，不声称可立即杀死任意阻塞的第三方 Python 调用。
