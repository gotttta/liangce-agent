# Agent 新架构设计方案

> 状态：草稿，待讨论确认
> 日期：2026-09-28

## 背景与核心约束

**最终产物是机台上运行的确定性 CV 算法**，不是单张图的标注。

- 机台只能运行传统 CV 算法（OpenCV、skimage），不能运行 SAM 或深度学习模型
- 没有现成的人工标注数据集，也不会要求用户逐张标注
- Handbook 只作为视觉参考，不会枚举所有目标
- 用户在一轮结束后给反馈，不需要实时监督

**当前 v2 的核心问题：** 复查靠模型看图打分，分数不稳定，迭代没有客观方向，算法越改越差。

---

## 核心思路：SAM 掩膜只做参考答案

SAM 在开发侧为每张样本图生成一份精确掩膜，经用户一次确认后固定下来作为"地面真值"。之后算法迭代的好坏，全部靠这份参考掩膜打 IoU 分——不再让模型看图复查。

```
[Handbook 参考图]
        ↓ 模型理解要标什么
[SAM 候选掩膜] → 用户点"对/不对" → [固定参考掩膜]
                                           ↓
                              算法迭代循环（可自主跑多轮）
                                           ↓
                              [交付：机台 CV 算法]
```

---

## 两个阶段

### 阶段一：生成参考掩膜（每张样本图只做一次）

1. 模型读 Handbook，理解目标类型（阵列孔、颗粒缺陷、线宽等）
2. 根据目标类型选分支：
   - **阵列类**：SAM 全图生成候选 → 模型选编号 → 复查删误选
   - **单缺陷类**：模型给粗框 → SAM 生成多个候选掩膜 → 模型挑最合适的
3. 叠加图发给用户确认（一次点击，不需要画框）
4. 确认后写入 `workspace/references/<image_id>/mask.npy` 和 `meta.json`，不再修改

用户操作：看叠加图，说"可以"或"这个不是"/"这里漏了"。反馈直接转成 SAM 负点或正点，重新生成，再确认。

### 阶段二：迭代出机台算法（反复跑，直到分数够好）

核心循环：

```
当前最优算法
    ↓
在全部参考图上运行
    ↓
和参考掩膜对比，算每张图的 IoU + 目标数量误差 + 测量误差
    ↓
汇总分数 > 当前最优？
    ├── 是：更新最优，记录参数
    └── 否：丢弃，不会越改越差
    ↓
告诉模型哪里错了（多检/漏检/边界偏差，附图和坐标）
    ↓
模型修改算法结构或参数 → 重新跑
```

Agent 可以自主跑几十轮，不需要用户盯着。用户的反馈（"这个不是"）加进评分即可，不需要重新标注。

## 算法形式

机台算法就是现在 `core/operators/` 里的那些算子的组合，输出 `MaskArtifact`，然后交给 `skills/` 里的测量代码。格式不变，换的只是怎么生成和迭代这条流水线。

```python
# 算法是一个参数化的算子序列，可以序列化为 JSON
pipeline = [
    {"op": "local_contrast", "clip_limit": 0.02, "tile_grid": 8},
    {"op": "bright_threshold", "sensitivity": 1.6, "min_area_px": 30},
    {"op": "morphology_open", "radius": 2},
]
```

参数搜索交给程序（网格或贝叶斯），模型决定算子结构（加一步去噪、换阈值策略等）。

## 新的图结构（替换 v2）

```
START
  ↓
prepare          # 读输入、加载参考掩膜
  ↓
has_reference?
  ├── 否 → gen_reference    # 阶段一：生成参考掩膜
  │         ↓ 用户确认
  │         └──────────────┐
  └── 是 ──────────────────┘
                ↓
          iterate           # 提出新算法版本
                ↓
          score             # 在参考图上跑，算 IoU
                ↓
          improved?
            ├── 是 → promote（更新最优）→ iterate（继续改进）
            └── 否 → iterate（换方向）
                ↓（达到目标分数或预算耗尽）
          human_gate        # 展示最优结果，等用户确认
                ↓
          finish
```

比 v2 少了 `quality_review`、`review_evidence`、`validate_submission` 这些节点——它们解决的是"怎么判断好坏"的问题，现在由 IoU 分数代替了。

## 评分指标

| 指标 | 说明 | 权重（可调） |
|------|------|-------------|
| 平均 IoU | 预测掩膜和参考掩膜的交并比，均值 | 高 |
| 目标数量误差 | abs(预测数 - 参考数) / 参考数 | 中 |
| 面积误差 | 各目标面积的相对误差均值 | 中 |
| 误检率 | 参考里没有但预测有的目标数量 | 高 |

综合分 = IoU × (1 - 误检率惩罚) × (1 - 数量误差惩罚)，都在 [0, 1]，越高越好。

## 设计决策

### 1. 参考掩膜最少需要多少张？

至少 5 张，最好 10 张。3 张容易对样本过拟合——算法在这 3 张上分数好，换一张新图就崩。

实际操作分两步走：先用 5 张迭代出初版算法，用户确认效果后再加 5 张验证泛化。这样每次用户只需要看 5 张确认图，负担不大。参考掩膜生成速度：每张 30–70 秒，10 张大约 10 分钟，不是瓶颈。

### 2. 用户确认界面

文字回复足够，第一版不做图上标注界面。理由：用户只需要说"可以"或指出哪里不对，后者直接转成 SAM 的负点/正点重跑一次。用户指的是"这个区域不对"，不是精确边界——精确边界仍然是 SAM 的活，做点击界面带来的信息增量有限，成本却很高。等流程稳定后可以考虑简单的 web 确认界面。

### 3. 算子搜索范围

`core/operators/defect.py` 里大约有：强度反转、百分位裁剪、局部对比度增强（CLAHE）、锐化（USM）、双边去噪、阈值、形态学，参数约 10 个。搜索空间不大。

策略分两层：模型负责选算子结构（加不加去噪、换哪种阈值），贝叶斯搜索负责调参数。在这个规模下，50–100 次迭代就能收敛，每次在 10 张图上约 10 秒，完全可接受。

### 4. 低对比度缺陷的参考掩膜质量问题

坏的参考答案比没有参考答案更危险，不能强行用一份 SAM 填满框的掩膜来驱动迭代。

做法：生成掩膜时同时记录 SAM 的最佳 IoU score。若 score < 0.7，在确认图旁边标注"分割质量低，建议确认"。用户说"不对"时，进入负点/正点修正流程；修正几次还是不好，就把这张图标记为 `skip_scoring: true`——它只用于人工验证最终结果，不参与 IoU 打分，不会把迭代方向带偏。

### 5. 自主迭代的轮数预算

按分数提升速率决定，而不是固定轮数。

规则：连续 5 轮综合分提升不超过 0.01，暂停并展示当前最优结果给用户；或综合分已达 0.85 以上，主动停下来提交。另设硬上限 100 轮防死循环。这样阵列孔类任务（通常 20 轮收敛）不会空跑，低对比度缺陷（可能需要 50 轮）也不会被卡死。
